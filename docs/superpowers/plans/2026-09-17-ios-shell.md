# DataRover iOS Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a sideloadable iOS app that boots the DataRover core with touch pen, power/option buttons, software keyboard, and Files-based ROM/package import.

**Architecture:** New `ios/DataRover/` Xcode project: a `DataRoverCore` static-lib target compiling the SUBTARGET=datarover file set for arm64/iOS (no SDL, headless OSD stub), plus a SwiftUI app target driving the 9-function C ABI. Touch maps to pen coordinates; keyboard arrives via a small new `datarover_key_event` ABI addition.

**Tech Stack:** Xcode 16+, SwiftUI (iOS 16+), MetalKit framebuffer view, C ABI bridge, `fileImporter`, `UIKeyInput`.

**Spec:** `docs/superpowers/specs/2026-09-17-ios-shell-design.md`

## Global Constraints

- Sideload dev build (free Apple ID, personal team); no App Store submission in this plan.
- ROM stays user-supplied via Files; packages in the app container.
- Core ABI names verbatim from `src/libdatarover/datarover_core.h`: `datarover_create/destroy/framebuffer_bytes/framebuffer_size/pen_down/pen_move/pen_up/install_package/install_package_named`.
- iOS 16+, arm64 + simulator. No GENie work; no SDL in the iOS link.
- Single-finger pen; power/option buttons match mac pulse semantics.

- Produces: booting app with touch pen consumed by Tasks 3-4

- [ ] **Step 1: Write the C bridge**

```swift
// CoreBridge.swift — thin wrapper, no logic beyond the ABI
import Foundation
func coreCreate(nvram: String, cfg: String, rom: String) -> UnsafeMutableRawPointer?
func coreFramebuffer(of handle: UnsafeMutableRawPointer) -> (bytes: UnsafePointer<UInt8>?, size: Int)
func corePen(_ handle: UnsafeMutableRawPointer, phase: PenPhase, x: Int, y: Int)
```

Backed by a `CoreBridge.h` declaring the fork functions with `NS_ASSUME_NONNULL` nullability matching the header contract (framebuffer may be NULL — null-check before blit).

- [ ] **Step 2: Write the Metal framebuffer view**

```swift
struct EmulatorView: UIViewRepresentable {
    var handle: UnsafeMutableRawPointer
    func makeUIView(context: Context) -> MTKView { /* 480x320 texture, aspect-fit */ }

}
```

 Treasurer: 2bpp → RGBA8 upload per frame via the ABI pointer; skip frame when NULL. Coordinator owns a `CADisplayLink` driving `datarover` frame advance + blit.
